# 表单

表单是最容易做难看的界面：一堆框、几个按钮，没有视觉主角。
但表单也是**用户唯一需要集中注意力**的地方。做好的表单是安静、清楚、不出错。

规则条目在规则库（`search.py "inline validation" --domain ux`），
这篇给的是**填一条信息的顺序**，以及每一步的取舍。

---

## 一、先把信息分组，再画框

拿一张表就开始画输入框，一定会画成一堵墙。**先看用户填一条信息要跨几个概念**：

```
概念1：这是什么        → 名称
概念2：什么时候执行    → 周期 + 具体时间
概念3：具体做什么      → 类型 + 内容
概念4：由谁执行        → 账号
```

每组之间加一个小标题，组内字段紧挨着。用户的眼睛沿着分组走，不会漏项。
不分组时，用户要靠记住「刚才那个是填什么的」。

**字段数砍到最少。** 每多一个字段就多一处流失。
问：这一步能不能由系统推断？能不能给默认值？能不能只在必要时才出现
（渐进披露）？

---

## 二、每个字段的四件事

### 标签：可见，不要用 placeholder 当标签

placeholder 在有值之后消失，用户没法回头确认这个框是干什么的。
而且对比度普遍不达标——浅灰字在浅底上，读不清。

```html
<label for="task-name">任务名称</label>
<input id="task-name" type="text" autocomplete="off">
```

标签在上方（纵向表单）比在左侧（横向表单）更易读：
中文标签长度不固定，左置标签会让输入框起始位置乱跳。

必填项在标签后加 `<span aria-hidden="true">*</span>`，
**不要只靠星号**——色盲用户和屏幕阅读器用户看不出来。

### 描述：只在真正需要时写

输入框下方一行小字，写清格式、限制、单位：

```
延迟时间（秒）  [60        ]
                0–3600 之间的整数
```

不需要说明的字段就别写。一屏都是说明文字，等于没说明。

### 默认值：给最常见的那个

让用户在每次执行时都改一遍同样的东西，是把默认值做错了。

默认值要**真的能用**——填好就能提交，不需要改。不是给个占位符让人去改。

### 校验：失焦时校验，不边打边骂

```bash
python scripts/search.py "inline validation blur" --domain ux
```

- **失焦（blur）时校验**，不是每敲一个键就报红。
  边打边骂是敌意的：用户还没打完第一个字符就被告知格式错误。
- **提交时校验全部**，且把焦点移到第一个出错的字段。
- 校验通过后**实时消除错误提示**，别让红字挂着。

### 错误：就在字段下面，说清怎么办

```
延迟时间
[60                    ]
↑ 这一项必须是 0–3600 之间的整数
```

三条硬要求（`Error Placement` 规则）：

1. 位置在出错字段**正下方**，不是页面顶部。
2. 说清**怎么改**，不是只说「格式错误」。
3. 用 `aria-describedby` 把错误文案关联到输入框，屏幕阅读器能读到。

## 三、按钮和提交

### 一个表单只有一个主按钮

次要动作降级：改成文字按钮，或放到右侧，用次要样式。
两个同样醒目的主按钮等于没有主按钮。

### 提交按钮写动词

```
[保存]        ← 泛泛
[创建任务]     ← 明确
[确认删除]     ← 明确，且危险色
```

### 加载中：按钮原位转圈

按钮进入 loading 时**不要改变宽度**，否则整行会晃。
做法：文字 `color: transparent` 占住原位，`::after` 绝对定位放 spinner。

### 关闭表单前提示未保存

有未保存改动时，点关闭/取消要确认。
只提示「确定放弃？」，不用给「保存并关闭」——除非用户频繁需要边填边存。

---

## 四、校验时机与位置速查

| 时机 | 做什么 |
| --- | --- |
| 页面加载 | 不校验（用户还没动） |
| 字段失焦 | 校验这一个字段 |
| 字段变有效 | 立刻消除该字段的错误提示 |
| 点击提交 | 校验全部，聚焦第一个错误字段 |
| 提交成功 | toast 或状态变化，关闭表单或重置 |

---

## 五、危险表单

删除、重置密码、清空数据这类表单：

- 确认框写出**对象名**和**后果**（「将永久删除 12 条记录，不可恢复」）。
- 危险按钮用 danger 色，**默认焦点落在取消上**。
- 输入确认（要求键入对象名）只在后果不可逆且对象较多时才用——
  它摩擦大，滥用只会让人机械地敲上去。

---

## 六、其他容器（复用表单的判断）

搜索框、单行编辑、筛选条不用完整表单规则：

- **搜索框**：label 可省略（有 `aria-label`），但要有搜索图标或占位说明。
- **单行编辑**（表格内改名）：失焦或回车提交，Esc 取消。
  规则库：`search.py "inline edit" --domain ux`。
- **筛选条**：每项默认折叠到高级筛选，主筛选不超过 3 项。

## 自查

- [ ] 字段按用户心智分了组，组内有小标题
- [ ] 标签可见且在输入框上方，必填不只靠星号
- [ ] 有默认值的字段，默认值真的能用
- [ ] 失焦才校验，变有效立刻消除错误
- [ ] 错误在字段正下方，说清了怎么改，并关联了 aria-describedby
- [ ] 一个表单只有一个主按钮，按钮写的是动词
- [ ] 提交中按钮尺寸不变
- [ ] 有未保存改动时关闭会提示
- [ ] 危险表单确认框写出了对象名和后果，默认焦点在取消
