# 交互与状态

界面好看是静态的，能不能用是动态的。这篇管**点下去之后发生什么**：
每个可操作控件的六种状态、加载与空态、错误恢复、危险操作确认。

规则条目散在规则库（`search.py "确认对话框" --domain ux`），这篇给的是
**把它们组织成一个界面的顺序**。先看状态，再看反馈，最后看表单。

---

## 一、每个可操作控件都有六个状态

按钮、链接、开关、列表项、表格行——凡能手点的，六态齐全才算做完。
缺任何一态，用户都会在某一刻不知道该点哪。

| 状态 | 视觉 | 触发 |
| --- | --- | --- |
| 静止 rest | 基准 | 默认 |
| 悬停 hover | 轻微变化 + `cursor: pointer` | 指针设备才有；触屏设备不要做 |
| 按下 active | 更明显一层，或缩放 0.98 | 按住的瞬间 |
| 焦点 focus | **可见焦点环**，2px 实心 + 2px 偏移 | 键盘导航 |
| 禁用 disabled | 降透明度 + `cursor: not-allowed` | 条件不满足 |
| 加载 loading | 原位转圈，**尺寸不变** | 请求进行中 |

三条容易做错的：

**loading 不改变按钮尺寸。** 文字换成 spinner 时按钮宽度会跳，整行跟着晃。
做法是保留文字占位、只让文字透明（`color: transparent`）再叠加 spinner，
或用 `position:absolute` 居中放 spinner。按钮的宽高在任何状态下都不许变。

**hover 只在真能 hover 的设备上做。** `@media (hover: hover) and (pointer: fine)`
里才写 hover 样式。触屏设备上 hover 会「粘住」——点完按钮颜色变深不再弹回，
用户以为还选中了。桌面端统一加这条 media query，不靠判断 UA。

**禁用要有理由。** 按钮灰了但不说为什么，是最让人恼火的一种。
至少给 `title` 说明（如「请先选择分组」）；能从上下文推断就更���。

## 二、焦点环：唯一不能省的

键盘用户 Tab 到哪，指针用户看不出来。查规则库：

```bash
python scripts/search.py "focus visible keyboard navigation ring" --domain ux
```

**验证必须派发真实按键。** 用脚本调 `element.focus()` 验证是错的——
`:focus-visible` 只在真实键盘导航时匹配，程序化聚焦不算键盘意图，
同样代码两次跑会给出不同的缺失列表（本 Skill 踩过这个坑）。
用：

```bash
node scripts/verify_focus.mjs <页面或 HTML>
```

写焦点环的两条实战约束：

1. **别用 `:where()`。** 它把整条规则特异性降为 0，压不过项目原有的
   `.toolbar input{outline:none}`，结果是焦点环被盖掉、键盘焦点比改之前更不可见。
   特异性不够时用带类名的选择器。
2. **实心按钮上的环要更亮。** 常规主色环压在同色系按钮上会糊。主按钮用白环或
   更亮的色，不要沿用全局 `--focus-color`。

## 三、反馈：加载、空、错、成功

### 加载

- 快（<300ms）不显示任何指示器。闪一下的 spinner 比没有更让人分神。
- 慢且会改变布局 → 骨架屏，**形状贴近真实内容**。
- 慢但不改变布局 → 就地转圈，不要整页遮罩。
- 超过 1s 的操作给进度或剩余时间，让人知道还要等多久。

骨架屏的行高列宽要和真实行一致，否则数据填进去时页面会跳——那是
`Content Jumping` 反模式。

### 空状态

最常被做错的一态。三段缺一不可：

1. **发生了什么**：「还没有计划任务」
2. **为什么**：「创建后到点会自动执行」——顺带说清这个产品的价值
3. **下一步**：「新建第一个任务」+ 一个真能点的按钮

空状态里不放插画就算合格；放插画则插画要矮（不超过一屏的 1/5），
否则它比文字抢眼。插画不是必需项。

### 错误

- **错误信息放在出错的地方旁边**，不堆在页面顶部让人找。
- 说清**怎么办**，不是只说错了什么。「密码错误」→「密码错误，请重新输入，或点右上角忘记密码」。
- 保留用户已填的内容，不要清空。
- 可恢复的错误要给恢复路径（重试、改哪一项）。

### 成功

- 轻量操作用 toast，**3–5 秒自动消失**，同一时刻只显示一个。
- 影响后续的操作（保存、创建）用持久反馈：状态标签变化、行出现在列表里。
  别让用户靠「有没有弹个提示」来判断操作成没成。

## 四、危险操作

删除、覆盖、批量停用这类不可逆操作，**必须确认**，且确认框要写出对象名：

```
删除任务「每日备份」？
该任务的执行记录会一并保留，但无法再恢复调度。
```

三处细节：

1. **确认框写出具体对象**，不要只写「确定要删除吗」——用户不知道删的是哪条。
2. **说清后果**，尤其是连带影响（会一并删掉什么、能不能恢复）。
3. **破坏性按钮本身别和普通按钮挨着**。确认框里「取消」在左、「删除」在右，
   危险按钮用 danger 色；主按钮默认聚焦到**取消**上，回车不会误删。

更稳妥的做法：能用撤销就不用确认框（删除后给 5 秒撤销条）。
确认框阻塞用户的操作，撤销条不阻塞。能撤销的操作优先给撤销。

## 五、动效：只给状态变化

动效的作用是让用户看懂「什么变成了什么」，不是装饰。

| 变化 | 时长 | 缓动 |
| --- | --- | --- |
| 悬停、按下 | 100–150ms | `ease-out` |
| 展开折叠、出现消失 | 200–250ms | `ease-out` |
| 弹窗进出场 | 200–300ms | 进 `ease-out`，出 `ease-in` 且**比进更快** |
| 页面区块出场 | 400–600ms | `ease-out`，错开 60–80ms |

- **出场比入场快**。东西进场要让人看清，出场只需知道「走了」，拖沓的退场最烦人。
- **不要动 width/height/left/top** 做动画，用 `transform` 和 `opacity`——
  前者每帧触发重排，后者走合成层。规则库：`search.py "animation" --domain ux`。
- **必须响应 `prefers-reduced-motion`**：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

前庭功能障碍者会因为大幅动效产生眩晕。这一条不是可选项。

- 只有一个地方值得留显眼动效：**主动作的那一刻**。比如任务执行成功的那一下。
  其余地方保持安静。
